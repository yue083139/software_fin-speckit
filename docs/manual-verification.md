# 人工驗證手冊（交組員執行）

> 需求 P-05：系統除 AI 自動驗證外**須人工驗證**。本檔把各卡 `verification.md` 的「人工驗證」段整理成可照做的場次，給組員一次跑完。
> 本檔在兩個 repo 逐位元組相同。兩組 `server/`、`web/` 程式碼逐字相同，**在任一 repo 跑一次即可**，但要記下是哪個 repo 與 commit。
> 新卡合入時，把該卡的人工驗證步驟加成新場次（或併入既有場次），並在 §5 加一列。

## 1. 執行前準備（約 10 分鐘）

1. 安裝：Python 3.12＋[uv](https://docs.astral.sh/uv/)、Node.js 24、GNU make、Git Bash（Windows）。
2. 在 repo 根目錄：

   ```bash
   git switch dev && git pull
   uv sync --project server --group dev
   make web-install
   make dev
   ```

3. 終端機會印出**老師頁網址**（含老師金鑰）。學生頁一律開 `http://127.0.0.1:8000/`。
4. 建議用一個瀏覽器視窗開老師頁，另開**無痕視窗**或不同瀏覽器開學生分頁（同一組只能一台裝置；分頁被拒時改用另一個瀏覽器設定檔）。
5. 每個場次開始前：老師頁按「重置活動」（只在「已結束」時可按；會保留題目與設定、清空作答），或在終端機 `Ctrl+C` 後重新 `make dev`（伺服器重啟即清空活動，學生分頁要重新選組）。
6. 夾具都在 `tests/fixtures/guided-notes/`：`single.xlsx`（6 單題）、`group.xlsx`（4 題，第 1、2 題為題組）、`variant.xlsx`（版面不同的 5 題）、`reference.xlsx`（含參考答案欄）。
7. 「從連結匯入」與「匯回 Google 試算表」兩步需要 Google 帳號：把 `group.xlsx` 上傳到自己的 Google 雲端硬碟並以 Google 試算表開啟，共用設為「知道連結者可檢視」。

**看 WebSocket 訊息**（隔離檢查要用）：學生分頁按 F12 → Network（網路）→ 篩選 `WS` → 點 `ws` 連線 → Messages（訊息）頁籤，逐筆看伺服器送來的 JSON。

## 2. 怎麼記錄

- 每一步照「做什麼 → 應看到什麼」對照，符合就在 §5 該場次打 ✅，不符打 ❌，並寫下**實際看到什麼**（截圖放 PR 或群組皆可，**不要**截到老師金鑰網址）。
- ❌ 不要自己改程式：開 GitHub issue，標題「人工驗證：場次 X 第 N 步」，附重現步驟、截圖、repo 與 commit（`git log --oneline -1`）。
- 全部跑完後把 §5 表格填好送 PR（C 檔，分支 `docs/manual-verification-results`），負責人再把結果抄進各卡 `verification.md` 的「結果」欄。

## 3. 場次

### 場次 A：經典搶答完整流程（第一期五卡，約 25 分鐘）

對應卡：`app-skeleton`、`guided-notes-import`、`buzz-answering`、`results-view`、`guided-notes-export`。

**A1 進場與階段同步（app-skeleton）**

1. 開三個分頁：老師頁、學生「第1組」、學生「第2組」。
2. 再開一個分頁到首頁 ⇒「第1組」按鈕停用並顯示「（已加入）」，按不下去（首頁只在載入時讀取加入狀態；若首頁比第1組加入早開，按下會顯示「此組已有裝置加入，請老師釋放後再加入」）。
3. 老師頁看到第1組、第2組「已加入」；按第2組的「釋放」⇒ 第2組分頁顯示「尚未加入組別或組別已被老師釋放」。第2組重新加入。
4. 尚未匯入題目時按「開始搶答」⇒ 顯示「尚未匯入題目，不能開始搶答」，階段仍為「準備中」。

**A2 匯入（guided-notes-import）**

5. 依序上傳 `single.xlsx`、`group.xlsx`、`variant.xlsx`，題目清單分別為 **6 題**、**4 題**（第 1、2 題各 2 子題）、**5 題**（第 2 題 3 子題、第 4 題 2 子題）。
6. 把 §1 第 7 步的 Google 試算表連結貼到「從連結匯入」⇒ 結果與上傳 `group.xlsx` 相同。
7. 學生分頁在「準備中」看到題號清單，**看不到題目敘述**。

**A3 搶答與作答隔離（buzz-answering）** — 先以 `group.xlsx` 匯入，再加一個「第3組」分頁

8. 老師按「開始搶答」⇒ 三個學生分頁同步變「搶答中」。
9. 第1組對第 3 題送出「甲」，第2組對第 3 題送出「乙」。
10. 第1組對第 1 題（題組）只填一個子題 ⇒ 送出按鈕無法按。
11. 第2組畫面**不出現**「甲」或任何「第 3 題已被搶」的提示；第2組的 WebSocket 訊息**沒有**「甲」。
12. 第1組第 3 題已鎖定，不能再送出。
13. 第3組對第 4 題送出任意答案。

**A4 結果（results-view）**

14. 搶答中：老師表即時出現答案與順位、得主格變綠；學生頁**沒有**結果區塊。
15. 老師按「結束搶答」⇒ 三個學生頁顯示每題得主與答案、本組順位、各組得題數，且與老師表一致（第 3 題得主第1組「甲」）。

**A5 匯出（guided-notes-export）**

16. 按「匯出 Guided Notes」，檔名為「group-搶答結果.xlsx」（以連結匯入時固定為「Google 試算表-搶答結果.xlsx」）。
17. 用 Excel 開啟：作答格內是得主答案，題組為「（1）答案」「（2）答案」，其他格與框線不變；沒人搶的題空白。
18. 在 §1 第 7 步的 Google 試算表「檔案 → 匯入 → 上傳 → 取代試算表」上傳匯出檔 ⇒ 答案出現在原填空格。

### 場次 B：只計對錯模式（game-mode-framework，約 10 分鐘）

1. 重置；老師匯入 `reference.xlsx`；開學生分頁第1組、第2組。
2. 老師「模式」選「只計對錯」⇒ 兩個學生分頁都顯示「模式：只計對錯」。開始搶答後模式單選停用。
3. 第1組第 1 題答「GPU」、第2組第 1 題答「cpu」；第1組第 3 題答任意文字。
4. 老師按「結束搶答」⇒ 階段「判定中」、顯示「尚有 3 筆未判定」、「揭曉結果」停用；學生分頁顯示「老師判定中…」；學生 WebSocket 訊息**看不到**他組答案，也看不到參考答案「CPU」。
5. 老師按「採用全部建議」⇒ 剩 1 筆（第 3 題無參考答案）；手動判第 3 題後按「揭曉結果」。
6. 學生分頁看到每筆 ✓／✗、「最早答對：第2組（cpu）」、欄名「得分」。老師匯出，第 1 題作答格為「cpu」。

### 場次 C：雙倍分數題（question-settings，約 5 分鐘）

1. 重置；**模式選回「經典搶答」**（重置會保留上一場的模式）；匯入 `group.xlsx`；題目清單勾第 3 題「雙倍分數」⇒ 學生分頁第 3 題出現「雙倍分數」標記。
2. 開始搶答後勾選框消失（只剩標記）。
3. 第1組先、第2組後送出第 3 題；第2組另送第 4 題；結束。
4. 結果：第1組 **2 分**、第2組 **1 分**；欄名「得分」；第 3 題標「雙倍分數」。
5. 重置活動後第 3 題仍為雙倍；重新匯入後全部恢復 1 倍、欄名回到「得題數」。

### 場次 D：時間計分模式（mode-timed-scoring，約 10 分鐘）

> 時間計分活動前**不先發紙本學習單**（負責人 2026-11-14 確認）。

1. 重置；匯入 `group.xlsx`，模式選「時間計分」⇒ 題目清單出現「時限」欄，把第 1 題設 10 秒。
2. 開學生分頁第1組、第2組；老師按「開始搶答」→「開放下一題」⇒ 學生只看到第 1 題與倒數，第 2 題以後看不到輸入欄。
3. 第1組約 2 秒時送出、第2組不送；倒數到 0 時兩個學生分頁**同時**顯示「已結束作答，等待揭曉」（不需老師操作）。
4. 第2組畫面此時已沒有輸入欄，無法再送出（伺服器端「關閉後送出回 409『這一題目前沒有開放作答』」由 `server/tests/test_timed_mode.py` 與 `probes/results/2026-11-12-timed-flow.txt` 守，人工不必驗）。
5. 老師判第1組正確 →「揭曉本題」⇒ 第1組看到「本組答對，+8xx 分」左右（分數＝`(20010 − 作答毫秒) // 20`：2 秒約 900、3 秒約 850，越快越高）；第2組看到「本組未作答」與名次表，名次表**沒有分數欄**；第2組 WebSocket 訊息看不到第1組答案與分數。
6. 老師未揭曉時「開放下一題」「結束活動」停用；揭曉後可開下一題或結束活動；結束後學生看到完整結果與各組分數。

### 場次 E：組隊模式（team-mode，第三期）

第三期卡合入後補上步驟；屆時以該卡 `verification.md` 的人工驗證段為準。
