# 人工驗證手冊（交組員執行）

> 需求 P-05：系統除 AI 自動驗證外**須人工驗證**。本檔把各卡 `verification.md` 的「人工驗證」段整理成可照做的場次，給組員一次跑完。
> 本檔在兩個 repo 逐位元組相同。兩組 `server/`、`web/` 程式碼逐字相同，**在任一 repo 跑一次即可**，但要記下是哪個 repo 與 commit。
> 新卡合入時，把該卡的人工驗證步驟加成新場次（或併入既有場次），並在 §5 加一列。

## 1. 執行前準備（約 10 分鐘）

1. 安裝：Python 3.12＋[uv](https://docs.astral.sh/uv/)、Node.js 24、GNU make、Git Bash（Windows）。
2. 在 repo 根目錄：

   ```bash
   git switch dev && git pull
   uv sync --project server --group dev
   make web-install
   make dev
   ```

3. 伺服器就緒後會**自動以預設瀏覽器開老師頁**（easy-setup；網址列載入後只剩 `#/teacher`）；終端機仍印老師頁網址（含老師金鑰）當備援。學生頁一律開 `http://127.0.0.1:8000/`。
4. 建議用一個瀏覽器視窗開老師頁，另開**無痕視窗**或不同瀏覽器開學生分頁（同一組只能一台裝置；分頁被拒時改用另一個瀏覽器設定檔）。
5. 每個場次開始前：老師頁按「重置活動」（只在「已結束」時可按；會保留題目與設定、清空作答），或在終端機 `Ctrl+C` 後重新 `make dev`（伺服器重啟即清空活動，學生分頁要重新選組）。
6. 夾具都在 `tests/fixtures/guided-notes/`：`single.xlsx`（6 單題）、`group.xlsx`（4 題，第 1、2 題為題組）、`variant.xlsx`（版面不同的 5 題）、`reference.xlsx`（含參考答案欄）。
7. 「從 Google 試算表匯入」與「匯出到 Google 試算表」兩步需要：①已建好 OAuth 用戶端——老師頁最上方「開始前的設定」清單的 Google 列若顯示「未設定」，到「Google 帳號」區照設定精靈六步完成（儲存後不用重啟；也可沿用既有 `.env`）；②你的 Google 帳號已登記為測試使用者（精靈第 4 步）；③把課程「題組＋單題」範本「檔案 → 建立副本」到自己的雲端硬碟（或把 `group.xlsx` 上傳後以 Google 試算表開啟），記下網址。

**看 WebSocket 訊息**（隔離檢查要用）：學生分頁按 F12 → Network（網路）→ 篩選 `WS` → 點 `ws` 連線 → Messages（訊息）頁籤，逐筆看伺服器送來的 JSON。

## 2. 怎麼記錄

- 每一步照「做什麼 → 應看到什麼」對照，符合就在 §5 該場次打 ✅，不符打 ❌，並寫下**實際看到什麼**（截圖放 PR 或群組皆可，**不要**截到老師金鑰網址）。
- ❌ 不要自己改程式：開 GitHub issue，標題「人工驗證：場次 X 第 N 步」，附重現步驟、截圖、repo 與 commit（`git log --oneline -1`）。
- 全部跑完後把 §5 表格填好送 PR（C 檔，分支 `docs/manual-verification-results`），負責人再把結果抄進各卡 `verification.md` 的「結果」欄。

## 3. 場次

### 場次 A：經典搶答完整流程（第一期五卡，約 25 分鐘）

對應卡：`app-skeleton`、`guided-notes-import`、`buzz-answering`、`results-view`、`guided-notes-export`。

**A1 進場與階段同步（app-skeleton）**

1. 啟動後老師頁自動開啟，最上方「開始前的設定」清單顯示 Google、手機連線、題目三列狀態；再開兩個學生分頁：學生「第1組」、學生「第2組」。
2. 再開一個分頁到首頁 ⇒「第1組」按鈕停用並顯示「（已加入）」，按不下去（首頁只在載入時讀取加入狀態；若首頁比第1組加入早開，按下會顯示「此組已有裝置加入，請老師釋放後再加入」）。
3. 老師頁看到第1組、第2組「已加入」；按第2組的「釋放」⇒ 第2組分頁顯示「尚未加入組別或組別已被老師釋放」。第2組重新加入。
4. 尚未匯入題目時按「開始搶答」⇒ 顯示「尚未匯入題目，不能開始搶答」，階段仍為「準備中」。

**A2 匯入（guided-notes-import）**

5. 依序上傳 `single.xlsx`、`group.xlsx`、`variant.xlsx`，題目清單分別為 **6 題**、**4 題**（第 1、2 題各 2 子題）、**5 題**（第 2 題 3 子題、第 4 題 2 子題）。
6. 老師頁點「開始前的設定」的 Google 列跳到「Google 帳號」區（未設定時先照設定精靈完成，見場次 H），按「以 Google 帳號登入」⇒ 新分頁到 Google 同意（遇「尚未驗證這個應用程式」按繼續）⇒ 新分頁顯示「登入完成，可關閉此分頁」、老師頁顯示「已登入：<你的帳號>」。把 §1 第 7 步的試算表網址貼到連結欄按「從 Google 試算表匯入」⇒ 題目清單與上傳 `group.xlsx` 相同（第 1、2 題各 2 子題），並出現「開啟 Google 試算表副本」連結；你的雲端硬碟多一份「<原標題>_作答情況」。
7. 學生分頁在「準備中」看到題號清單，**看不到題目敘述**。

**A3 搶答與作答隔離（buzz-answering）** — 沿用 A2 第 6 步從 Google 試算表匯入的題目（內容同 `group.xlsx`；A5 第 16 步要用這一場），再加一個「第3組」分頁

8. 老師按「開始搶答」⇒ 三個學生分頁同步變「搶答中」，每題輸入欄上方出現題目敘述（第 1、2 題的兩個子題各有自己的敘述；question-text）；老師頁題目清單在準備階段就看得到敘述。
9. 第1組對第 3 題送出「甲」，第2組對第 3 題送出「乙」。
10. 第1組對第 1 題（題組）只填一個子題 ⇒ 送出按鈕無法按。
11. 第2組畫面**不出現**「甲」或任何「第 3 題已被搶」的提示；第2組的 WebSocket 訊息**沒有**「甲」。
12. 第1組第 3 題已鎖定，不能再送出。
13. 第3組對第 4 題送出任意答案；第2組對第 2 題（題組）兩個子題都填後送出（A5 第 16 步要看題組答案位置）。

**A4 結果（results-view）**

14. 搶答中：老師表即時出現答案與順位、得主格變綠；學生頁**沒有**結果區塊。
15. 老師按「結束搶答」⇒ 三個學生頁顯示每題得主與答案、本組順位、各組得題數，且與老師表一致（第 3 題得主第1組「甲」）。
15a. （answer-review）老師表第 3 題候選為第1組「甲」，旁邊有「答對」「答錯」；按「答錯」⇒ 候選換成第2組「乙」，老師表與三個學生頁的第 3 題得主同步變第2組、第1組該題標 ✗、得題數第1組 −1、第2組 +1。
15b. 對第 3 題候選第2組按「答對」⇒ 第 3 題顯示「已鎖定」，「答對」「答錯」消失、出現「重設本題」。另在按「答錯」時快速連點兩下不會跳過一組（第二下提示「這一組不是目前要檢查的答案，請重新整理」）。
15c. 對第 4 題按「重設本題」⇒ 提示「本題尚未檢查」；第 4 題仍為第3組（未檢查＝最快者）。

**A5 匯出（guided-notes-export）**

16. （以 A2 第 6 步從 Google 試算表匯入的那一場）按「匯出到 Google 試算表」⇒ 出現副本連結；開啟副本：副本名稱為「<原標題>_作答情況」；每題填空格是得主答案（第 1 題空白、第 2 題第2組、第 3 題「乙」——第 15b 步鎖定的第2組、第 4 題第3組）——題組子題的「（1）」「（2）」標籤不變、答案在標籤**右邊**那一格；沒人搶的題空白；其他格、格式與框線不變。**原試算表**完全沒變。
17. 按「下載 xlsx（備援）」，用 Excel 開啟：答案位置與第 16 步相同（只含值與合併、不含格式）。
18. 改以上傳 `group.xlsx` 匯入再跑一場、結束後按「匯出到 Google 試算表」⇒ 顯示「題目不是從 Google 試算表匯入，請改用下載 xlsx」；按「下載 xlsx（備援）」⇒ 檔名「group_作答情況.xlsx」，題組答案在 H 欄、G 欄標籤不變。

### 場次 B：只計對錯模式（game-mode-framework，約 10 分鐘）

1. 重置；老師匯入 `reference.xlsx`；開學生分頁第1組、第2組。
2. 老師「模式」選「只計對錯」⇒ 兩個學生分頁都顯示「模式：只計對錯」。開始搶答後模式單選停用。
3. 第1組第 1 題答「GPU」、第2組第 1 題答「cpu」；第1組第 3 題答任意文字。
4. 老師按「結束搶答」⇒ 階段「判定中」、顯示「尚有 3 筆未判定」、「揭曉結果」停用；學生分頁顯示「老師判定中…」；學生 WebSocket 訊息**看不到**他組答案，也看不到參考答案「CPU」。
5. 老師按「採用全部建議」⇒ 剩 1 筆（第 3 題無參考答案）；手動判第 3 題後按「揭曉結果」。
6. 學生分頁看到每筆 ✓／✗、「最早答對：第2組（cpu）」、欄名「得分」。老師匯出，第 1 題作答格為「cpu」。

### 場次 C：雙倍分數題（question-settings，約 5 分鐘）

1. 重置；**模式選回「經典搶答」**（重置會保留上一場的模式）；匯入 `group.xlsx`；題目清單勾第 3 題「雙倍分數」⇒ 學生分頁第 3 題出現「雙倍分數」標記。
2. 開始搶答後勾選框消失（只剩標記）。
3. 第1組先、第2組後送出第 3 題；第2組另送第 4 題；結束。
4. 結果：第1組 **2 分**、第2組 **1 分**；欄名「得分」；第 3 題標「雙倍分數」。
5. 重置活動後第 3 題仍為雙倍；重新匯入後全部恢復 1 倍、欄名回到「得題數」。

### 場次 D：時間計分模式（mode-timed-scoring，約 10 分鐘）

> 時間計分活動前**不先發紙本學習單**（負責人 2026-11-14 確認）。

1. 重置；匯入 `group.xlsx`，模式選「時間計分」⇒ 題目清單出現「時限」欄，把第 1 題設 10 秒。
2. 開學生分頁第1組、第2組；老師按「開始搶答」→「開放下一題」⇒ 學生只看到第 1 題與倒數，第 2 題以後看不到輸入欄。
3. 第1組約 2 秒時送出、第2組不送；倒數到 0 時兩個學生分頁**同時**顯示「已結束作答，等待揭曉」（不需老師操作）。
4. 第2組畫面此時已沒有輸入欄，無法再送出（伺服器端「關閉後送出回 409『這一題目前沒有開放作答』」由 `server/tests/test_timed_mode.py` 與 `probes/results/2026-11-12-timed-flow.txt` 守，人工不必驗）。
5. 老師判第1組正確 →「揭曉本題」⇒ 第1組看到「本組答對，+8xx 分」左右（分數＝`(20010 − 作答毫秒) // 20`：2 秒約 900、3 秒約 850，越快越高）；第2組看到「本組未作答」與名次表，名次表**沒有分數欄**；第2組 WebSocket 訊息看不到第1組答案與分數。
6. 老師未揭曉時「開放下一題」「結束活動」停用；揭曉後可開下一題或結束活動；結束後學生看到完整結果與各組分數。

### 場次 E：組隊（team-mode，約 15 分鐘）

需要三個學生分頁（第1組 A、第1組 B、第2組）；同一組的兩個分頁請用不同瀏覽器或無痕視窗（組別憑證存在分頁裡）。

1. 重置；模式選「經典搶答」；匯入 `group.xlsx`；老師在「組別」區塊勾「組隊（一組多台裝置）」。
2. 第1組 A 分頁到首頁選「第1組」⇒ 學生頁顯示「本組邀請碼：XXXXXX」；老師頁第1組顯示「已加入（1 台）」與同一組邀請碼。
3. 第1組 B 分頁到首頁，不填邀請碼按「第1組」⇒ 顯示「邀請碼不正確」；填入 A 畫面上的邀請碼（可打小寫）再按 ⇒ 加入成功；老師頁第1組變「已加入（2 台）」。第2組分頁選「第2組」。
4. 老師按「開始搶答」⇒ A、B 學生頁不再顯示邀請碼（改提示向老師索取）；老師頁第1組的邀請碼換成新的。
5. A 在第 3 題輸入「甲」⇒ 約半秒後 B 的第 3 題出現「組內草稿：甲」與「套用」；按「套用」⇒ B 的輸入欄變成「甲」。第2組畫面沒有任何變化；第2組開發者工具的 WebSocket 訊息**沒有新訊息**、看不到「甲」。
6. B 送出第 3 題 ⇒ A 的第 3 題立刻變成「已送出：甲」，A 不能再送第 3 題。
7. 老師在組別區按第1組「釋放」⇒ A、B 都顯示「尚未加入組別或組別已被老師釋放」；老師頁第1組出現新的邀請碼。A 到首頁用**舊**碼加入 ⇒「邀請碼不正確」；用老師頁的新碼 ⇒ 加入成功。
8. 老師按「結束搶答」⇒ 結果與經典搶答相同（第 3 題得主第1組，答案「甲」）。

### 場次 F：手機掃碼（student-qr，約 5 分鐘）

前置：已安裝 cloudflared（`winget install --id Cloudflare.cloudflared -e`）；手機關掉 Wi-Fi 改用 4G。

1. 雙擊 `start.cmd` ⇒ 老師頁自動開啟；「學生連結」區顯示本機網址並提示「目前只在本機可連；要讓手機掃碼，按上方「開啟手機連線」」。（easy-setup 起移除 `start-tunnel.cmd`。）
2. 按「開啟手機連線」⇒ 按鈕變「手機連線建立中…」，約 5 秒後 QR code 換成 `https://….trycloudflare.com/`，下方提示「新網址約 1 分鐘後才連得上」；按「複製連結」變「已複製」。（未安裝 cloudflared 時改顯示「找不到 cloudflared」與安裝指令、「複製指令」鈕；裝好後再按一次即可，不用重啟。）
3. 手機掃 QR code ⇒ 開啟學生頁，可選第1組加入；電腦另開一個學生分頁選第2組。匯入題目、開始搶答，手機送出第 3 題 ⇒ 老師表即時出現，電腦第2組看不到。
4. 電腦瀏覽器改用公開網址開老師頁（`https://….trycloudflare.com/#/teacher?key=<金鑰>`）⇒ 顯示「老師頁只能在本機開啟」與「請用 http://127.0.0.1:8000 開老師頁。」，不會停在「連線中…」，看不到任何活動資料。
5. 搶答中按「關閉手機連線」⇒ 按鈕停用並提示「搶答開始後不能關閉手機連線」。重置活動後按「關閉手機連線」⇒ QR code 回到本機網址，工作管理員裡的 `cloudflared.exe` 少一個。
6. 再開一次手機連線後關閉視窗 ⇒ 手機學生頁斷線；工作管理員裡沒有殘留的 `cloudflared.exe`。

### 場次 G：老師金鑰不留在網址列（teacher-key-hidden，約 2 分鐘）

1. `make dev`（或 `start.cmd`），貼終端機印的老師頁網址 ⇒ 老師頁正常載入，網址列只剩 `http://127.0.0.1:8000/#/teacher`，不含 `key=`。
2. 按 F5 重新整理 ⇒ 仍是老師頁、資料照常更新。
3. 按瀏覽器「上一頁」不會回到含 `key=` 的網址（`replaceState` 已改寫這一筆紀錄）。註：瀏覽器「記錄」頁（Ctrl+H）與網址列自動完成仍可能保留最初貼上的完整網址，這是瀏覽器行為；錄影前可在新分頁貼網址、錄完刪除該筆記錄。
4. 關掉這個分頁，另開新分頁輸入 `http://127.0.0.1:8000/#/teacher` ⇒ 顯示整頁「老師金鑰錯誤」與「請用啟動伺服器時終端機印出的完整老師頁網址重新開啟，或回首頁重新輸入金鑰。」（新分頁沒有存金鑰）；在同一分頁改貼完整網址 ⇒ 錯誤頁消失、正常進入，網址列只剩 `#/teacher`。
5. 把網址改成 `#/teacher?key=錯誤` ⇒ 顯示同一整頁提示；再貼正確完整網址可進入。
6. 未登入 Google 時按「匯出到 Google 試算表」（需在「已結束」）⇒ 只顯示「請先以 Google 帳號登入」，**不會**跳到金鑰錯誤頁，按 F5 仍是老師頁。

### 場次 H：啟動即進老師頁與設定精靈（easy-setup，約 15 分鐘）

前置：要一個可登入的 Google 帳號；先把 repo 根目錄 `.env` 改名備份（例 `.env.bak`），模擬第一次使用。

1. 雙擊 `start.cmd` ⇒ 伺服器就緒後**預設瀏覽器自動開老師頁**；網址列一開始含 `#/teacher?key=…`，載入後只剩 `#/teacher`。終端機仍印老師頁與學生頁網址。
2. 老師頁最上方「開始前的設定」三列：Google 帳號「未設定」、手機連線「關閉（選用…）」、題目「尚未匯入」；點任一列 ⇒ 捲到對應區塊。
3. 「Google 帳號」區顯示「伺服器未設定 Google OAuth 用戶端」與六步精靈；第 1～5 步連結開到 Google Cloud Console 對應頁；第 5 步的重新導向 URI 按「複製」變「已複製」。
4. 照精靈在 Console 建立用戶端，把用戶端 ID 與密鑰貼進第 6 步按「儲存設定」⇒ 不重啟，該區變成「以 Google 帳號登入」與「目前用戶端：123456…apps.googleusercontent.com」；清單 Google 列變「已設定，尚未登入」；repo 根目錄出現 `.env`，內含兩行設定，資料夾裡沒有 `.env.tmp-*`。
5. 故意在密鑰欄貼錯（例 `abc`）按儲存 ⇒ 上方顯示「用戶端密鑰格式不符（應以 GOCSPX- 開頭）」，`.env` 不變。
6. 按「以 Google 帳號登入」完成登入 ⇒ 清單 Google 列「已登入 <帳號>」；此時「變更設定」「清除設定」不出現。登出後按「清除設定」⇒ 回到精靈，`.env` 兩行被移除、其他行保留。
7. 匯入題目 ⇒ 清單題目列「已匯入 N 題」；按「開始搶答」⇒ 清單消失（只在準備階段顯示）。
8. （選做，需一台缺 uv 或 Node.js 的電腦）雙擊 `start.cmd` ⇒ 問「要幫你用 winget 安裝嗎？(Y/N)」；直接按 Enter ⇒ 顯示手動安裝指令後結束；再雙擊輸入 Y ⇒ winget 安裝（可能跳出「是否允許變更」視窗，按「是」），裝完不必重開視窗即繼續啟動。
9. 測完把 `.env.bak` 改回 `.env`。

### 場次 I：前三名領獎台（results-podium，約 5 分鐘）

前置：照場次 A 匯入 `group.xlsx`，開老師頁與三個學生分頁（第1、2、3組）。

1. 經典搶答，讓第1組搶到兩題、第2組搶到一題、第3組都沒搶到，按「結束搶答」⇒ 老師頁「作答狀況與結果」上方出現「領獎台」：由左到右第 2 名第2組、第 1 名第1組（台最高）；第3組 0 分不上台；分數與表格最下列「得題數」一致。
2. 學生頁第1組 ⇒「搶答結果」下方同一個領獎台，第1組旁有「本組」；第2組分頁的「本組」標在第 2 名；第3組分頁沒有「本組」標籤。
3. 老師在作答狀況表把第1組某題按「答錯」（換到第 2 順位的組）⇒ 領獎台與學生頁即時跟著變；若變成同分 ⇒ 兩組並列同一名次，下一名跳號。
4. 按「重置活動」⇒ 領獎台消失；重新開始搶答、都沒有人送出就結束 ⇒ 不出現領獎台。
5. （選做）只計對錯或時間計分模式揭曉後 ⇒ 領獎台欄名顯示「得分」。

### 場次 J：即時搶答快訊（live-feed，約 3 分鐘）

前置：照場次 A 匯入 `group.xlsx`，開老師頁與兩個學生分頁（第1、2組），模式「經典搶答」。

1. 老師按「開始搶答」⇒ 老師頁不跳任何快訊。
2. 第2組送出第 3 題 ⇒ 老師頁右上角跳出「第2組 搶下第 3 題！」，約 3 秒後自動消失；通知裡沒有答案內容。
3. 第1組也送出第 3 題 ⇒ 跳出「第1組 送出第 3 題」。
4. 按 F5 重新整理老師頁 ⇒ 不會把已經送出的題目再跳一次。
5. 學生頁全程沒有快訊；按「結束搶答」後老師在作答狀況表按「答對／答錯」也不跳快訊。
