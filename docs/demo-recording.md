# Demo 影片錄製指南

> 給要錄 Demo 影片的人：照這份準備、照分鏡錄，錄完用檢查表自查。本檔在兩個 repo 逐位元組相同。
> 兩部影片（OpenSpec 版、SpecKit 版）展示**同一個產品**（兩組程式碼逐字相同），只有開場 15 秒不同，見 §4。
> 知識時點：2026-11-26（含 easy-setup：自動開老師頁、Google 設定精靈、一鍵手機連線）。

## 1. 課程要求對照

| 課程要求（期末專題說明「Demo 影片說明」「評分標準」） | 本指南怎麼做到 |
|---|---|
| 各大組錄 **2 部**（一部 OpenSpec、一部 SpecKit） | §4：兩部共用分鏡，只換開場 15 秒的開發方法展示 |
| 一部 **5 分鐘內**，上傳 **YouTube** | §3 分鏡合計 **4:40**，留 20 秒緩衝；§5 上傳設定 |
| 完整展示活動流程，含**老師端與至少 2 組學生端**畫面 | 第1組用手機掃 QR code、第2組用電腦學生分頁；每段都標明畫面要拍誰 |
| 評分看**內容完整性、講解流暢度、時間控管** | 分鏡每段有秒數、操作與旁白重點；§2 要求先彩排一次 |
| **程式碼、文件、Demo 影片須一致** | 只拍已合入 `dev`／`main` 的功能；按鈕文字照實際畫面念；開場帶到的文件就是 repo 裡那份 |

## 2. 錄前準備（約 20 分鐘，前一天先做一次彩排）

**活動資料**

1. Google 設定精靈已完成（設定精靈那段不在影片裡錄，太長；要展示就只帶 5 秒畫面）。
2. 把課程「題組＋單題」範本「檔案 → 建立副本」到自己的雲端硬碟，複製好網址（題組與題目敘述都要有，才拍得到第 1、2 題的子題敘述）。
3. 先跑一次完整活動當彩排，確認匯入、作答、結束、答對／答錯、匯出都正常。
4. 彩排後**重啟伺服器**（關掉黑色視窗再雙擊 `start.cmd`）：不能只按「重置活動」——它會保留題目，第 2 段清單會顯示「已匯入 4 題」，和旁白「題目尚未匯入」對不上。
5. 重啟會清掉 Google 登入與手機連線（權杖不落地、每次網址都不同），所以重啟後老師頁自動開好，依序：重新「以 Google 帳號登入」→ 按「開啟手機連線」→ **等約 1 分鐘** → 手機重新掃 QR code 確認連得上 → 手機回到學生頁首頁，先不要選組。
6. 開錄前看一眼「開始前的設定」清單：**Google 已登入、手機連線已開啟、題目尚未匯入**，三項都對才開錄。

**視窗配置（1920×1080 螢幕建議）**

| 位置 | 畫面 | 備註 |
|---|---|---|
| 左半 | 老師頁（`http://127.0.0.1:8000/#/teacher`） | 瀏覽器縮放 110%–125%，字才看得清楚 |
| 右上 | 第2組學生頁（電腦另一個瀏覽器視窗） | 用**另一個瀏覽器設定檔或無痕視窗**，避免和老師頁共用分頁狀態 |
| 右下 | 第1組：手機畫面鏡像 | Android 可用 scrcpy、iPhone 可用「iPhone 鏡像輸出」或 AirPlay 接收程式；不方便鏡像就讓第1組也用電腦視窗，手機只拍「掃 QR code」那一幕 |

**一定要藏起來的東西**

- **黑色伺服器視窗（終端機）**：裡面印著含老師金鑰的完整網址，錄影前最小化或移到另一個螢幕。
- **`.env` 與編輯器**：不要開著 `.env`；精靈的密鑰欄是遮蔽輸入，但不要在畫面上重貼密鑰。
- **瀏覽器網址列的歷史**：老師頁網址載入後只剩 `#/teacher`，但網址列自動完成可能跳出含 `key=` 的舊網址；錄影時不要在網址列打字，或用無痕視窗開老師頁。
- 通知：開「勿擾模式」。

**錄影工具**：OBS Studio（可同時擷取多個視窗與手機鏡像、輸出 1080p 30fps）；只錄單一視窗可用 Windows「Xbox Game Bar」（Win＋Alt＋R），但它錄不到多個視窗並排，不建議。旁白用耳麥，先錄 10 秒試音。

| 9 | 4:00–4:30 | 30 | 加分片段（§3.1 挑一個） | 先按「重置活動」回到準備階段（題目保留），再做下表操作 | 額外功能 |
| 10 | 4:30–4:40 | 10 | 老師頁或 repo 首頁 | 停在畫面 | 收尾：「兩個 repo、兩套開發方法、同一個產品；程式碼、規格與這部影片一致。」 |

### 3.1 加分片段（每段 10–30 秒，挑一兩個；總長超過就只挑一個）

第 9 段排在匯出之後，活動已是「已結束」；雙倍分數、模式、組隊只在準備階段能改。所以先在「已結束」按「**重置活動**」回到準備階段——題目會保留，正好直接示範；或把加分片段另外單獨錄好再剪進來。

| 片段 | 秒數 | 操作 | 旁白重點 |
|---|---|---|---|
| 雙倍分數 | 10 | 準備階段題目清單勾第 3 題「雙倍分數」→ 學生畫面出現標記 | 指定題目 ×2 分 |
| 時間計分 | 30 | 模式選「時間計分」→「開放下一題」→ 學生倒數作答 →「揭曉本題」看名次 | Kahoot 式：答越快分越高，伺服器計時；揭曉後只公開名次不公開他組分數 |
| 只計對錯 | 15 | 模式選「只計對錯」→ 結束後判定中 →「採用全部建議」→ 揭曉 | 比正確不比速度；參考答案欄預填建議 |
| 組隊 | 15 | 「組別與裝置」勾組隊 → 第二台裝置憑邀請碼加入同組 → 看到組內草稿 | 一組多台裝置，組內任一人送出代表全組 |

## 4. 兩部影片的差異（只換第 1 段 0:00–0:15）

| | OpenSpec 版 | SpecKit 版 |
|---|---|---|
| repo | `software_fin-openspec` | `software_fin-speckit` |
| 開場畫面 | 在 GitHub 打開一張變更卡，例 `openspec/changes/archive/2026-11-26-answer-review/`，依序快速點 `proposal.md` → `design.md` → `specs/` → `tasks.md`（各 3 秒） | 在 GitHub 打開 `.specify/memory/constitution.md` 捲到「原則 VII 圖表生成」（5 秒），再開 `diagrams/` 點一張 PNG，例 `012-answer-review-sequence.png`（5 秒），再帶 `specs/012-answer-review/plan.md`（5 秒） |
| 旁白 | 「本組用 OpenSpec：每個功能是一張變更卡，proposal、design、specs、tasks 四件套，評審後才實作。」 | 「本組用 SpecKit 並導入 Diagram First：憲章規定先畫組件圖、類別圖、時序圖，plan 以圖為藍圖，實作後核對圖與程式一致。」 |
| 第 2–10 段 | 相同 | 相同（從 SpecKit repo 啟動，畫面與行為一致） |

兩部分開錄，不要用同一段剪接兩次：評分會看程式碼、文件、影片是否一致，各從自己的 repo 啟動最穩。

## 5. 錄後檢查表

- [ ] 開錄前清單是「Google 已登入」（彩排後重啟伺服器並重新登入）。
- [ ] 開錄前清單是「手機連線已開啟」，且已等約 1 分鐘、手機重新掃碼確認連得上。
- [ ] 開錄前清單是「題目尚未匯入」（彩排後是重啟伺服器，不是只按重置活動）。
- [ ] 片長 ≤ 5:00（YouTube 顯示的長度）。
- [ ] 畫面中**沒有**：終端機、含 `key=` 的網址、`.env`、用戶端密鑰、個人信件或通知。
- [ ] 看得到老師端與**至少 2 組**學生端（第1組手機、第2組電腦）。
- [ ] 完整流程都有：匯入 → 學生加入 → 開始搶答 → 作答隔離 → 結束與結果 → 答對／答錯檢查 → 匯出到試算表。
- [ ] 按鈕文字與畫面和 repo 現行版本一致（錄影前 `git switch dev && git pull`，或依課程要求用 `main`）。
- [ ] 旁白清楚、音量足；必要時加字幕（YouTube 自動字幕可再手動修正）。
- [ ] 上傳 YouTube：標題含組別與「OpenSpec 版」或「SpecKit 版」；瀏覽權限依課程要求，未規定時用「不公開」（有連結的人才看得到）；不要設「私人」，助教會看不到。
- [ ] 兩部影片連結填進課程 Google 表單；README 或繳交說明同步附上連結。
