# 兩組功能一致協議（parity）

> 本檔在 OpenSpec 組與 SpecKit 組兩個 repo **逐位元組相同**（判據：`make gate-parity SIBLING=<另一 repo 路徑>`）。
> 對應需求 P-03：兩組產出的系統功能要一致，實作期間任何改動要與另一組討論。

## 1. 規則

1. **凡改使用者可感知行為的卡**（OpenSpec 的 change／Spec Kit 的 feature），開卡時先在本檔 §4「功能清單」登記或改行，並在 §5「變更紀錄」加一行；**兩個 repo 同批改本檔**（各開一個 PR，PR 描述互相連結）。
2. 一邊的規格先定稿，另一邊**照同一行為寫自己工具格式的規格**，不互抄檔案——兩組的評分各看自己工具的產物。
3. 行為以本檔＋`docs/requirements.md` 為準；兩組各自的規格與本檔衝突時，**改規格**，或回本檔改行並通知另一組。
4. 不改行為的卡（文件、重構、門禁）不必登記。

## 2. 共用技術選型（兩組相同，降低 Demo 與比對成本）

| 層 | 選型 | 理由（屬取捨） |
|---|---|---|
| 後端 | Python 3.12、FastAPI、WebSocket、uv 管理依賴 | 階段同步需要伺服器推播；與門禁腳本同語言 |
| 試算表 | openpyxl 讀寫 xlsx | 保留原檔格式與合併儲存格，回寫填空格後仍可匯回 Google Sheets |
| 前端 | React＋Vite＋TypeScript，npm 管理 | 老師端與學生端同一套元件，以路由區分 |
| 儲存 | 伺服器記憶體；**第一期不做 JSON 快照**，伺服器重啟即清空活動（Demo 前提醒老師結束後先匯出）；快照列為第二期 | 本機模擬即可（需求 §1），不引入資料庫 |
| 執行 | 本機單一伺服器；多個瀏覽器分頁模擬老師與各組 | 需求明示不必架設對外伺服器 |

選型由第一張功能卡的 design／plan 正式寫入；若一組要偏離，先改本表並通知另一組。

## 4. 功能清單（建議拆卡順序；兩組卡名一致，便於對照）

| 卡名 | 涵蓋需求 | 摘要 | OpenSpec 狀態 | SpecKit 狀態 |
|---|---|---|---|---|
| `app-skeleton` | R-01、R-11 | 前後端骨架；老師（啟動時產生的老師金鑰）／學生（選組取得組別憑證，一組一台裝置，老師可釋放）進場；預設 4 組、可設 2–12 組；階段狀態機（準備→搶答中→已結束，預留判定中）；WebSocket 只在該連線的畫面內容改變時推送 | 已實作（待合入） | 已實作（待合入） |
| `guided-notes-import` | R-02、X-01 | 匯入 xlsx（≤5 MB）或「知道連結者可檢視」的 Sheets 連結；表頭別名（題號／編號／題次／No、作答／答案／回答／Answer）定位欄，題號格縱向合併範圍定位題組；只在準備階段；學生只看到題號與子題標籤 | 已實作（待合入） | 已實作（待合入） |
| `buzz-answering` | R-03、R-06、R-07、R-09、R-10 | 須先匯入題目才能開始；全部題目同時開放；每組每題只能送出一次（不可修改）；題組一次送出全部子題；答案 ≤200 字、不可空白或含控制字元；順位依伺服器接收序；搶答中學生看不到他組是否送出與順位 | 已實作（待合入） | 已實作（待合入） |
| `results-view` | R-04、R-08 | 老師即時看「題號 × 組別」表（答案、順位、得主、各組得題數）；學生只在結束後看到每題得主、得主答案、全部組別答案與順位、各組得題數 | 已實作（待合入） | 已實作（待合入） |
| `guided-notes-export` | R-05 | 只在結束後可匯出；每題得主答案寫回原檔作答格（佔位符取代、否則接在標籤後，一律存為文字）；無人搶答題不變；檔名 `<原檔名>-搶答結果.xlsx` | 已實作（待合入） | 已實作（待合入） |
| `csv-export` | X-02 | 題號、組別、答案、搶答順位匯出 CSV | 未開 | 未開 |
| `fair-ranking` | X-03 | 公平順位機制：已搶答成功的組別下一題延遲計入順位（併入模式框架，見 `docs/trd-game-modes.md`） | 未開 | 未開 |
| `game-mode-framework` | X-04 | 模式介面、`ScoringRule`、判定階段、伺服器計時；經典搶答改寫為規則之一且行為不變（TRD T-01～T-04、T-06） | 未開 | 未開 |
| `question-settings` | X-04 | 題目倍率與時限設定；**雙倍分數題**（TRD T-05） | 未開 | 未開 |
| `mode-buzz-fallback` | X-03、X-04 | 搶答＋錯誤遞補：最先送出者判錯則依順位遞補（TRD M1） | 未開 | 未開 |
| `mode-timed-scoring` | X-04 | **時間計分**（Kahoot 式公式）與只計對錯兩種模式、每題揭曉後排行榜（TRD M2、M3） | 未開 | 未開 |
| `team-mode` | X-04 | **組隊模式**：一組多台裝置，組分數合併方式待裁（TRD M4） | 未開 | 未開 |

狀態值：未開／提案中／實作中／已實作（待合入）／已合入。

`game-mode-framework` 以下各卡的技術需求見 `docs/trd-game-modes.md`，競品依據見 `docs/research/competitors.md`；排程在核心五張卡合入之後。
